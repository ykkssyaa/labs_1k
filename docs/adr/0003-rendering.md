# ADR-0003. Изолированный слой рендеринга поверх html/template

- Статус: принято
- Дата: 2026-10-24

## Контекст
Нужны темы, наследование, partial-шаблоны и гарантированное экранирование
пользовательских данных. Задание допускает «собственный шаблонный механизм или
строго изолированный слой рендеринга».

## Решение
Пакет `internal/render`: тема — каталог `themes/<имя>/` с `layouts/`,
`partials/`, `pages/` и `theme.json` (`extends` — родительская тема).
Файл ищется в теме, затем в родителях (наследование тем). Страница наследует
макет через блоки `{{define "content"}}`. Экранирование — контекстное
экранирование `html/template` (HTML, атрибуты, URL, JS). Markdown материалов
преобразуется собственным минимальным конвертером, который сначала экранирует
весь текст, а потом добавляет разрешённую разметку; ссылки только `http(s)`,
`mailto` и относительные.

Остальной код получает только `Engine.Render(...)`, `html/template` наружу не торчит.

## Отклонённые альтернативы
- **Свой шаблонизатор с нуля.** Красиво для отчёта, но экранирование по
  контексту (атрибут, URL, script) — самое опасное место, легко ошибиться.
  Предложение агента написать свой движок отклонено, см. журнал ИИ.
- **text/template.** Не экранирует — прямая дорога к XSS.
- **SPA на фронтенде поверх API.** Хуже для SEO, а серверный рендер всё равно
  нужен по заданию.
- **Сторонний markdown (goldmark).** Отдаёт сырой HTML, нужен ещё санитайзер;
  подмножества разметки для издания хватает.

## Последствия
+ XSS через поля материалов закрыт по построению и проверен тестом.
− Возможности markdown ограничены (заголовки, абзацы, списки, жирный, курсив,
  ссылки, цитаты).
