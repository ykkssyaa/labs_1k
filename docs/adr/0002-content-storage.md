# ADR-0002. Поля типов материалов хранятся в JSON-колонке

- Статус: принято
- Дата: 2026-10-24

## Контекст
Типы материалов задаются схемами в `content_types/*.json`. Новый тип должен
добавляться без правки ядра и без ручной миграции БД.

## Решение
Общие поля (заголовок, slug, статус, автор, даты, SEO) — обычные колонки таблицы
`entries`. Поля типа — объект в колонке `entries.data` (TEXT с JSON). Схема
типа валидирует `data` в ядре до записи. Фильтрация по полям типа при
необходимости — через `json_extract` SQLite.

## Отклонённые альтернативы
- **Таблица на каждый тип (DDL из схемы).** Добавление типа = генерация
  `CREATE TABLE`, изменение поля = `ALTER TABLE`, в SQLite ограниченный. Ядро
  начинает зависеть от генерации SQL — больше мест для ошибок агента.
- **EAV (entity–attribute–value).** Гибко, но каждое чтение материала — N строк
  и сборка объекта; типы значений теряются; запросы сложные.
- **Документная БД (MongoDB).** Лишний сервис на стенде, теряем внешние ключи для
  таксономии.

## Последствия
+ Тип добавляется файлом, БД не меняется.
+ Снимок ревизии = тот же JSON, round-trip тривиален.
− Целостность полей типа держит ядро, а не БД — поэтому инварианты покрыты тестами.
− Изменение схемы требует миграции данных — сделали шаги `migrations` в схеме.
