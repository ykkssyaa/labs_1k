# Аннотированная трасса агентской сессии

Полный экспорт: [INDEX.md](INDEX.md) → `stage-0.md` … `stage-5.md` (сессия
`e2948cc7-cf91-4477-8cc3-101d41592637`, Claude Code, Claude Opus 5.5). Экспорт сделан
скриптом `scripts/export_trace.py` из журнала Claude Code; рассуждения модели не
включены, личные email и домашний каталог заменены заглушками.

Ниже — пять эпизодов, которые показывают, как шла работа с агентом. Время — МСК.

## Эпизод 1. Порция по спецификации проходит с первого раза (этап 2, 20:22)

**Трасса** (`stage-2.md`): агент пишет `content/schema.go`, `validate.go` и табличный
тест по разделу «Порция 2.1», затем:

```
$ go test ./internal/content/
ok  	github.com/ykkssyaa/vestnik-cms/internal/content	0.003s
```

**Комментарий.** Спецификация перечисляла типы полей, правила и ошибки схемы — тест
строился прямо по этим спискам (27 случаев полей, 12 битых схем). Чем точнее раздел
спецификации, тем меньше итераций: это единственная крупная порция без единой правки.

## Эпизод 2. Тест инварианта находит ошибку ядра (этап 2, 20:26)

```
--- FAIL: TestSearchSurvivesTransitionAndIgnoresCase (0.00s)
    service_test.go:287: поиск "эрмитаж" после submit нашёл 0
```

**Комментарий.** Агент реализовал переход статуса через общий `EntryRepo.Update`, а
`Get` не читает служебную колонку `search` — при любом переходе поисковая строка
затиралась пустой. Ошибку поймал тест, написанный по спецификации («поиск находит
материал и после смены статуса»). Решение — отдельный `UpdateStatus`, который меняет
только статус и даты. Вывод: переход жизненного цикла — не «правка содержимого», и это
разделение теперь видно в коде.

## Эпизод 3. Агент «убивает» сам себя — урок для разрешающей модели (этап 3, 20:39)

```
$ pkill -f 'smoke/vestnik serve'; cd vestnik-cms && git add -A && git commit ...
Exit code 144
```

**Комментарий.** Шаблон `pkill -f` совпал с командной строкой оболочки, в которой он
выполнялся, — оболочку убило, коммит не выполнился. Агент заметил это по коду выхода и
повторил команду без `pkill`. По итогам в `.claude/settings.json` добавлены
`"Bash(pkill:*)"` и `"Bash(killall:*)"` в `deny`.

**Важно про харнесс в этой сессии.** Сессия была запущена из родительского каталога
`study/`, поэтому проектные настройки `vestnik-cms/.claude/settings.json` (разрешения и
хуки) в ней **не действовали** — они вступают в силу, когда Claude Code запускается в
каталоге репозитория (так и нужно делать на защите). Хуки проверены отдельными запусками:

```
$ echo '{"tool_name":"Edit","tool_input":{"file_path":".../migrations/0001_init.sql"}}' | scripts/hooks/guard-migrations.sh
Миграция internal/store/migrations/0001_init.sql уже в git и могла быть применена.
Не меняй её — создай новую миграцию с следующим номером.
exit=2          ← вызов инструмента заблокирован

$ echo '{"tool_input":{"file_path":".../0008_new.sql"}}' | scripts/hooks/guard-migrations.sh
exit=0          ← новая миграция разрешена

$ echo '{"tool_input":{"file_path":".../bad.go"}}' | scripts/hooks/gofmt-check.sh
Файл .../bad.go не отформатирован gofmt. Запусти gofmt -w .../bad.go.
exit=2
```

Если бы хук gofmt работал в сессии, итерации 17 и 35 журнала (коммиты без
форматирования) не случились бы — правка была бы отклонена сразу.

## Эпизод 4. «Всё зелёное», а сборка с нуля падает (этап 5, 20:56)

```
#11 [build 4/6] RUN go mod download
#11 0.136 go: go.mod requires go >= 1.26.0 (running go 1.25.14; GOTOOLCHAIN=local)
```

**Комментарий.** На этапе 3 `go mod tidy` подтянул `golang.org/x/crypto@latest`
(требует Go 1.26). Локально `GOTOOLCHAIN=auto` молча скачал Go 1.26, поэтому `make check`
был зелёным полтора этапа. Ошибку показало только развёртывание из чистого клона в
образе `golang:1.25`. Та же ошибка была в итерации 5 — агент повторил её, потому что
правило о версиях не было записано. Теперь оно в `CLAUDE.md` (правило 9), а Makefile
выставляет `GOTOOLCHAIN=local`.

## Эпизод 5. Галлюцинация в шаблоне: `$` — не текущий элемент (этап 5, 20:58)

```
level=ERROR msg="render site" page=home theme=classic err="render classic/home: template:
classic/pages/home.html:4:73: executing \"content\" at <$>: wrong type for value;
expected *store.Entry; got *site.View"
```

**Комментарий.** Агент написал `{{entryPath $}}` внутри `{{with index . 0}}`, считая `$`
текущим материалом. В Go-шаблонах `$` — корневые данные страницы. Ветка с обложкой
начала исполняться после правки из итерации 31 (герой главной — материал с картинкой),
а e2e-тесты материалов с обложками на главной не проверяли. Исправление — переменная
`$hero`; новый e2e-тест на старом шаблоне падает:

```
public_test.go:314: classic /: код 500, изображение в разметке: false
```

Вывод для спецификаций: критерий «каждая ветка шаблона исполняется тестом» добавлен в
`CLAUDE.md` (правило 11).
