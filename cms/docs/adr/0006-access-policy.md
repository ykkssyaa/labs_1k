# ADR-0006. Матрица прав — конфигурация config/roles.json

- Статус: принято
- Дата: 2026-10-24

## Контекст
Не менее трёх ролей; права на операции и на типы материалов. На защите нужно
добавить роль или право в живой сессии.

## Решение
Роли и права описаны в `config/roles.json`: у роли список действий
(`entry.create`, `entry.edit.own`, `entry.transition.publish`, …, `*`) и список
типов материалов (`*` — все). `access.Policy.Can(user, action, resource)`
проверяет действие, тип и владение (`.own` — только свои материалы и только в
статусе `draft`). Код проверяет права только через `Policy`.

## Отклонённые альтернативы
- **Роли в коде (`if user.Role == "editor"`).** Новая роль = правка десятка
  обработчиков; агент обязательно пропустит один.
- **Роли и права в таблицах БД с UI редактирования.** Гибче, но для трёх-четырёх
  ролей — лишний экран и миграции; конфиг проще проверить тестом.
- **Внешний движок политик (Casbin, OPA).** Лишняя зависимость ради матрицы 4×20.

## Последствия
+ Новая роль = блок в JSON (0 правок кода), новое право = JSON + одна проверка там,
  где действие выполняется.
− Изменение прав требует перезапуска сервера.
