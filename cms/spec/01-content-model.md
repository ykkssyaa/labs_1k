# 01. Контент-модель

Спецификация написана до генерации кода. Код ядра обязан ей соответствовать;
расхождение — повод отклонить результат агента.

## 1. Материал (entry)

Общие поля есть у любого материала, их хранит ядро:

| Поле | Тип | Правило |
|---|---|---|
| `id` | int | автоинкремент |
| `type` | string | имя типа из реестра схем |
| `title` | string | обязательно, 1–200 символов |
| `slug` | string | `[a-z0-9-]+`, 1–120, уникален в пределах типа; если пуст — строится из заголовка транслитерацией |
| `status` | enum | `draft`, `review`, `published`, `archived` |
| `author_id` | int | автор материала |
| `seo_title`, `seo_description` | string | метаданные для поисковиков, ≤ 70 и ≤ 160 символов |
| `data` | object | поля типа (см. ниже), JSON |
| `created_at`, `updated_at`, `published_at` | time | `published_at` ставится при первой публикации |
| `categories`, `tags` | []term | связи с таксономией |

## 2. Типы материалов

Тип — это JSON-схема в каталоге `content_types/`. Добавить тип = положить
файл. Ядро не знает имён типов.

| Тип | URL | Поля `data` |
|---|---|---|
| `article` — Статья | `/articles/{slug}` | `lead` text*, ≤300; `body` markdown*; `cover` media; `reading_time` int 1..120 |
| `news` — Новость | `/news/{slug}` | `lead` text*, ≤280; `body` markdown*; `source_url` url; `is_breaking` bool |
| `review` — Рецензия | `/reviews/{slug}` | `subject` string*; `subject_kind` select* (книга, фильм, спектакль, выставка, ресторан); `rating` int* 1..10; `body` markdown*; `cover` media |
| `event` — Событие | `/events/{slug}` | `starts_at` datetime*; `ends_at` datetime, не раньше `starts_at`; `venue` string*; `price` string; `body` markdown; `cover` media |
| `page` — Страница | `/{slug}` | `body` markdown*; `show_in_menu` bool; `menu_order` int 0..100 |

`*` — обязательное поле.

### Формат схемы

```json
{
  "name": "review",
  "version": 1,
  "label": "Рецензия",
  "label_plural": "Рецензии",
  "url_prefix": "reviews",
  "fields": [
    {"name": "rating", "label": "Оценка", "type": "int", "required": true, "min": 1, "max": 10}
  ],
  "migrations": []
}
```

Типы полей: `string`, `text`, `markdown`, `int`, `bool`, `date`, `datetime`,
`select`, `url`, `media`.

Правила: `required`, `min_length`, `max_length`, `min`, `max`, `pattern`,
`options` (для `select`), `after` (имя другого поля даты, значение не раньше
него), `default`.

Схема с ошибкой (неизвестный тип поля, дубль имени, `select` без `options`,
`after` на несуществующее поле, `url_prefix` занят другим типом) не загружается,
сервер не стартует и пишет, что не так.

### Миграции схем

У схемы есть `version`. При старте реестр сравнивает версию с записанной в БД.
Если версия выросла, применяются шаги из `migrations` с `to_version` больше
сохранённой: `add_field` (ставит `default` во всех материалах типа),
`rename_field`, `remove_field`. Каждый применённый шаг пишется в таблицу
`schema_migrations`. Понижать версию нельзя — ошибка старта.

## 3. Жизненный цикл

```
            submit            publish
  draft ───────────▶ review ──────────▶ published ──archive──▶ archived
    ▲                  │                    │                     │
    └────── reject ────┘                    │                     │
    ▲                                       │                     │
    └────────────── unpublish ──────────────┘                     │
    ▲                                                             │
    └────────────────────────── restore ──────────────────────────┘
```

- Прямого перехода `draft → published` нет: любой материал проходит модерацию.
- Права на переход проверяются в ядре (`content.Service.Transition`) через
  политику доступа, а не в обработчиках HTTP.
- Переход создаёт запись в журнале действий.

## 4. Ревизии

- Каждое сохранение материала (создание, правка, откат, миграция схемы) создаёт
  ревизию: полный снимок `title`, `slug`, `seo_*`, `data`, `categories`, `tags`.
- Номер ревизии растёт в пределах материала с 1.
- Откат к ревизии N не удаляет историю, а создаёт новую ревизию с содержимым N.
- Смена статуса не создаёт ревизию (статус — не содержимое).

## 5. Таксономия

- Два словаря: `category` (рубрики, иерархия через `parent_id`) и `tag` (плоский).
- Термин: `id`, `vocabulary`, `name`, `slug` (уникален в словаре), `parent_id`.
- Связь «материал — термин» — таблица `entry_terms` с внешними ключами и
  `ON DELETE CASCADE`; рубрика не может быть родителем самой себе (проверка в ядре,
  цикл тоже).
- Меню сайта строится из рубрик верхнего уровня и страниц с `show_in_menu`.

## 6. Медиа

- Загрузка JPEG, PNG, GIF до 10 МБ; остальные типы — отказ.
- Метаданные: имя файла, MIME, размер, ширина, высота, `alt`, кто загрузил.
- Производные размеры: `thumb` 320×320 (обрезка по центру), `medium` 800 по
  ширине, `large` 1600 по ширине; производные не больше оригинала.
- Поле типа `media` хранит `id` медиафайла.

## 7. Инварианты (проверяются тестами ядра)

1. Материал не сохраняется, если данные не проходят схему типа.
2. `slug` уникален в пределах типа.
3. Неизвестные поля в `data` отбрасываются (не хранятся молча).
4. Статус меняется только по разрешённым переходам.
5. `published_at` ставится при первой публикации и не меняется после.
6. Номера ревизий идут подряд без пропусков.
7. Сериализация материала в JSON и обратно даёт тот же материал (round-trip).
8. Откат восстанавливает ровно снимок выбранной ревизии.
