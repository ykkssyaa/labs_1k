# 05. Этап 4 — шаблонный слой и публичная часть

## Порция 4.1. Markdown и экранирование (`internal/render/markdown.go`)

`render.Markdown(src string) template.HTML` — единственный источник
`template.HTML` из пользовательских данных.

1. Весь текст сначала экранируется (`html.EscapeString`), разметка добавляется после.
2. Блоки: абзацы (пустая строка), `#`/`##`/`###` → `h2`/`h3`/`h4` (h1 — заголовок
   материала), списки `- ` и `1. `, цитаты `> `. Одиночный перевод строки → `<br>`.
3. Строчные: `**жирный**`, `*курсив*`, `` `код` ``, `[текст](адрес)`.
4. Ссылки только `http`, `https`, `mailto`, относительные (`/…`, `#…`). Иначе — текст без ссылки.
   Внешние ссылки получают `rel="nofollow noopener"`.

Тест на внедрение разметки: `<script>`, `onerror=`, `javascript:` в разном регистре,
разметка в заголовке материала — на сайте, в панели и в API выводятся как текст.

## Порция 4.2. Темы (`themes/classic`, `themes/newspaper`)

- `classic` — базовая тема: `layouts/base.html`, partial-шаблоны `header`, `footer`,
  `menu`, `card`, `field`, `pager`, `meta`; страницы `home`, `list`, `entry`, `page`, `search`, `404`.
- `newspaper` — вторая тема, `"extends": "classic"`: свой CSS, свой `header` и `card`,
  остальное наследует.
- Страница материала: если в теме есть `pages/entry-<тип>.html` — используется она,
  иначе общий `entry.html`, который выводит поля по схеме (новый тип отображается
  без нового шаблона).
- Активная тема хранится в таблице `settings`, меняется администратором
  (`/admin/settings`, право `settings.manage`).

## Порция 4.3. Публичные страницы (`internal/web/site`)

| Путь | Что |
|---|---|
| `/` | свежие материалы и блоки по типам |
| `/{префикс типа}` | лента материалов типа, пагинация |
| `/{префикс}/{slug}` | страница материала |
| `/{slug}` | статическая страница (тип с пустым префиксом) |
| `/section/{slug}` | рубрика (с подрубриками) |
| `/tag/{slug}` | тег |
| `/search?q=` | поиск по опубликованным |

- Только `published`; остальное — 404.
- Меню: рубрики верхнего уровня + страницы с `show_in_menu`, по `menu_order`.
- Префиксы `admin`, `api`, `static`, `uploads`, `section`, `tag`, `search` зарезервированы —
  схема типа с таким `url_prefix` не загружается.

## Порция 4.4. REST API (`internal/web/api`)

- `GET /api/v1/types` — схемы типов.
- `GET /api/v1/entries?type=&category=&tag=&q=&page=&per_page=` — опубликованные
  материалы; `category`, `tag` — slug термина; `per_page` ≤ 100.
  Ответ: `{"items": [...], "meta": {"page", "per_page", "total", "pages"}, "links": {"self", "next", "prev"}}`.
- `GET /api/v1/entries/{id}` и `GET /api/v1/types/{type}/entries/{slug}`.
- `GET /api/v1/terms?vocabulary=category|tag`.
- Поля `media` раскрываются в объект с адресами вариантов.
- Ошибки — `{"error": "..."}` с кодом 400/404. CORS: `Access-Control-Allow-Origin: *` (только GET).

## Порция 4.5. SEO

- `<title>`: `seo_title` или заголовок; `description`: `seo_description`, иначе первое
  текстовое поле схемы, обрезанное до 160 символов.
- `canonical`, OpenGraph (`og:title`, `og:description`, `og:image` из первого поля `media`).
- `/sitemap.xml` — главная, ленты типов, рубрики, все опубликованные материалы с `lastmod`.
- `/robots.txt` — `Disallow: /admin/`, ссылка на sitemap.

## Порция 4.6. Сквозные тесты публичной части

Не меньше 3 сценариев через HTTP на поднятом сервере:
1. Автор пишет → редактор публикует → материал есть на главной, в рубрике, в меню
   (для страницы), в sitemap и API; после снятия с публикации — 404 везде.
2. Внедрение разметки в заголовок и текст — экранировано на сайте, в панели, в API.
3. Администратор переключает тему — меняется разметка публичных страниц.
4. Пагинация и фильтр по таксономии в API.
