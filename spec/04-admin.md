# 04. Этап 3 — панель администрирования

## Порция 3.1. Политика доступа (`internal/access`, `config/roles.json`)

Роли и права — конфигурация (ADR-0006).

```json
{
  "roles": {
    "editor": {
      "label": "Редактор",
      "types": ["*"],
      "permissions": ["entry.create", "entry.edit", "entry.transition.*", "..."]
    }
  }
}
```

Правило `Policy.Can(actor, action, res)`:

1. Неизвестная роль — запрещено.
2. Если `res.Type` задан и не входит в `types` роли (и там нет `*`) — запрещено.
3. Разрешено, если у роли есть `*`, само действие или маска `префикс.*`.
4. Разрешено, если у роли есть `действие.own`, `res.AuthorID == actor.ID` и
   материал в статусе `draft` (или статус не задан — создание).
5. Иначе запрещено.

### Матрица прав (стартовая)

| Действие | admin | editor | author |
|---|:-:|:-:|:-:|
| `admin.access` вход в панель | + | + | + |
| `entry.create` | + | + | + (кроме `page`) |
| `entry.edit` | + | + | только свои черновики |
| `entry.delete` | + | + | только свои черновики |
| `entry.rollback` | + | + | только свои черновики |
| `entry.list.any` видеть чужие материалы | + | + | − |
| `entry.transition.submit` | + | + | только свои |
| `entry.transition.publish/reject/unpublish/archive/restore` | + | + | − |
| `entry.batch` пакетные операции | + | + | − |
| `media.upload` | + | + | + |
| `media.delete` | + | + | − |
| `taxonomy.manage` | + | + | − |
| `audit.view` | + | + | − |
| `stats.view` | + | + | − |
| `users.manage` | + | − | − |
| `settings.manage` (тема сайта) | + | − | − |

Критерий: не меньше 10 параметризованных тестов «роль → действие → ресурс → да/нет»;
тест, что роль из JSON без правки кода получает права (новая роль `corrector`
в тестовом конфиге).

## Порция 3.2. Аутентификация и сессии (`internal/auth`)

По ADR-0005: bcrypt, сессия в БД (хэш токена), cookie `vestnik_session`
(`HttpOnly`, `SameSite=Lax`, срок 7 дней), CSRF-токен сессии в каждой POST-форме.
Неактивный пользователь войти не может, его сессии удаляются при блокировке.
Подкоманда `vestnik adduser email name role password`.

## Порция 3.3. Журнал действий (`store/audit.go`, миграция)

`audit_log(id, user_id, user_name, action, object, object_id, details, created_at)`.
Пишется в той же транзакции, что и действие (реализация `content.AuditSink`).
Журналируются: операции с материалами, переходы, откаты, термины, медиа,
пользователи, вход и выход. Экран журнала с фильтром по пользователю и действию.

## Порция 3.4. Экраны панели (`internal/web/admin`, тема `themes/_admin`)

| Экран | Путь | Что есть |
|---|---|---|
| Вход | `/admin/login` | форма, ошибка без уточнения «email или пароль» |
| Сводка | `/admin/` | счётчики по статусам, очередь модерации, мои черновики |
| Материалы | `/admin/entries` | фильтры: тип, статус, автор, рубрика, поиск; пагинация; чекбоксы и пакетные операции |
| Создание/правка | `/admin/entries/new?type=`, `/admin/entries/{id}` | форма строится из схемы типа; ошибки у полей; кнопки доступных переходов |
| Ревизии | `/admin/entries/{id}/revisions` | список, просмотр снимка, откат |
| Рубрики и теги | `/admin/terms` | создание, переименование, родитель, удаление |
| Медиатека | `/admin/media` | загрузка, превью, alt, удаление |
| Пользователи | `/admin/users` | создание, роль, блокировка |
| Журнал | `/admin/audit` | фильтры, пагинация |

Форма материала строится из схемы: `string`→input, `text`→textarea,
`markdown`→большая textarea, `int`→number, `bool`→checkbox, `date`→date,
`datetime`→datetime-local, `select`→select, `url`→url, `media`→выбор из медиатеки.

Автор видит только свои материалы (фильтр навязывается, если нет `entry.list.any`).
Модерация — список со статусом `review` и кнопками «Опубликовать» / «Вернуть».

Пакетные операции: выбранные материалы × действие (`submit`, `publish`,
`archive`, `delete`). Каждый материал проверяется отдельно; итог «выполнено N,
пропущено M» с причинами.

## Порция 3.5. Тесты

- Тесты доступа (порция 3.1) — не менее 10.
- HTTP-тесты: без входа редирект на `/admin/login`; POST без CSRF — 403;
  автор не открывает чужой материал и `/admin/users`.
- Сквозной сценарий администратора: вход → создание пользователя-автора → автор
  создаёт и отправляет материал → редактор пакетно публикует → запись в журнале.
